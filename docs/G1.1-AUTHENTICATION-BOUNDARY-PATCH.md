# Genesis G1.1 Authentication Boundary Patch

## Behaviour

- `/` renders a public SalesPilot landing page when no valid Supabase session exists.
- `/` renders the real workspace overview when a valid authenticated user exists.
- The authenticated display name is resolved from Supabase user metadata; no hard-coded user name remains.
- Sign out returns to `/`, where the public landing page is shown.
- `/campaigns/new` remains available before authentication so Business Discovery can happen first.
- The durable campaign draft remains available during sign-up and sign-in.
- Protected workspace routes redirect to sign-in and retain their intended return path:
  - `/campaigns`
  - `/campaigns/[id]`
  - `/companies`
  - `/replies`
  - `/opportunities`
  - `/focus`
  - `/settings`
- The anonymous New Campaign shell shows Sign in and Create account controls without presenting a false authenticated identity or workspace status.

## Database changes

None.

## Environment changes

None beyond the existing Supabase authentication variables.

## Verification

```bash
npm ci
npm run auth:boundary-check
npm run auth:draft-check
npm run typecheck
npm run build
```

## Manual test

1. Sign out.
2. Confirm `/` displays the public landing page and no personal name or workspace metrics.
3. Select **Start with your website** and complete Business Discovery anonymously.
4. Confirm the New Campaign shell shows authentication controls rather than a user identity.
5. Create an account or sign in.
6. Confirm the saved campaign draft resumes.
7. Launch the campaign.
8. Sign out and confirm the browser returns to the public landing page.
9. Open `/settings` while signed out and confirm redirect to `/sign-in?next=%2Fsettings`.
10. Sign in and confirm return to Settings.
