# Genesis G1.1 — Authentication Completion Patch

## What changed

- Added a secure email/password sign-in screen at `/sign-in`.
- Added server-side Supabase Auth token exchange at `/api/auth/sign-in`.
- Added server-side sign-out cookie clearing at `/api/auth/sign-out`.
- Added session refresh middleware.
- Kept organisation resolution server-side and membership-scoped.
- Redirects an unauthenticated launch to sign-in.
- Preserves and restores the approved campaign draft after sign-in.
- Added no third-party dependencies and no live credentials.

## Production setup

1. Confirm `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` exist in Vercel.
2. Enable Email/Password in Supabase Authentication providers.
3. Create or invite the production user in Supabase Authentication.
4. Insert an active `OWNER` or `ADMIN` organisation membership for that auth user.
5. Deploy, open `/sign-in`, authenticate, and repeat campaign launch.
