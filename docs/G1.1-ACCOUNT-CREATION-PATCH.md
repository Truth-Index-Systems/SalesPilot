# Genesis G1.1 Account Creation Patch

## What changed

- Added `/sign-up` using the existing SalesPilot authentication design.
- Added `POST /api/auth/sign-up` backed by Supabase Auth.
- New users automatically receive a tenant workspace and `OWNER` membership.
- Added a `Create account` link to the sign-in page.
- Added a `Sign in` link to the account creation page.
- Email-confirmation-enabled Supabase projects show a safe confirmation message; projects with confirmation disabled sign the user in immediately.

## Required migration

Run this manually in Supabase before deploying the patch:

```text
supabase/migrations/0003_genesis_account_signup.sql
```

The migration creates the service-role-only `provision_salespilot_workspace` function. It atomically creates the organisation and active owner membership, or reuses an existing active workspace for the user.

## Required environment variables

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

Do not expose the service-role key to the browser.

## Supabase Auth settings

Add the deployed application URL to Supabase Authentication URL Configuration. When email confirmation is enabled, users confirm their email and then return to `/sign-in`.

## Verification

1. Open `/sign-in` and select **Create account**.
2. Enter name, workspace name, email and an 8+ character password.
3. Complete email confirmation if enabled.
4. Sign in.
5. Verify a row exists in `organisations`.
6. Verify an `ACTIVE` `OWNER` row exists in `organisation_memberships` for the new Auth user.
7. Launch a campaign and confirm it persists.
