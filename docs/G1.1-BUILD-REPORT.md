# Genesis G1.1 Build Report

Implemented:

- Server-side Supabase session authentication without trusting browser organisation fields.
- Active organisation membership resolution.
- OWNER/ADMIN launch permission enforcement.
- Dedicated `CampaignLaunchService`.
- Atomic launch RPC with idempotency, approved Business DNA persistence/versioning, campaign config v1, customer timeline, and one `CampaignCreated` outbox record.
- Persisted campaign list and detail reads scoped to the authenticated organisation.
- Tenant-scoped RLS policies and no customer access to outbox/idempotency records.
- Customer-safe API errors and presentation labels.
- Development fallback limited to non-production and an explicit flag.

Build verification limitation:

The provided ZIP excluded `node_modules`. The execution environment's configured npm registry returned HTTP 404 for existing pinned dependencies including `zod@3.24.2`, so dependencies could not be restored and `npm run build` could not be completed in this environment. Run `npm ci && npm run build` using the normal public npm registry or the project's working CI/Vercel environment before deployment.
